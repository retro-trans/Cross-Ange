# Package analysis — preparation 0.1.0

Checked 2026-10-10. This is an analysis milestone, not a playable translation build.

## Verified local facts

The supplied package is a PS Vita base application for title ID `PCSG00597`, content ID `JP0700-PCSG00597_00-CROSSANGEGAME000`. Its physical and declared lengths agree at **925,548,400 bytes**. The extended PKG header identifies key type 2 and content type 0x15. There are **64 package items including directories**, not 64 script files. Application and package versions are `01.00`; minimum firmware shown by metadata is `03.360`.

`tools/pkg_probe.py` reads the header and the plaintext copy of SFO metadata. Its default mode only prints a sample; its optional output mode creates a new JSON file without overwriting existing files. The inspected metadata was saved to ignored `work/source/package-metadata.json`. It contains the verified title strings and line break, suitable for an initial title translation. It does not contain dialogue.

Official upstream pkg2zip was compiled locally. Its read-only `-l` check recognized the game's title and region before extraction. A subsequent `-x` run succeeded without a license argument. Output is in ignored `work/source/pkg/app/PCSG00597`. The original package was not rewritten. There are **54 extracted files totaling 925,548,907 bytes**, including packaging files generated by the extractor.

| `cpk/Ange.cpk` | 882,846,536 bytes | Filename suggests CRI middleware archive; contents still protected |
| `movie/movie_000.mp4` | 29,624,749 bytes | Protected contents |
| `sce_sys/manual/001.png` through `024.png` | 24 files | Protected contents; cannot inspect pages yet |
| `sce_pfs/files.db` | 12,288 bytes | Header `SCENGPFS` |
| `sce_pfs/unicv.db` | 677,888 bytes | Header `SCEIRODB` |

The archive's first four bytes are `D6 D9 F4 55`, rather than the expected `43 50 4B 20` (`CPK `). PNG samples do not have the PNG signature, and the XML template is not readable XML. Alongside the PFS metadata, these independent signature checks establish that unpacking the outer PKG has **not decrypted its protected filesystem layer**. Scanning those encrypted bytes for apparent Japanese strings would produce false candidates and would not measure translation workload.

Therefore the dialogue count, Japanese character count, archive member count, UI text coverage, and screen width limits remain **unknown**, rather than zero. No dialogue translation or patch can be reliably prepared from the current asset bytes.

## Practical next step

Place an already decrypted copy of this owned game's files in `incoming/PCSG00597-decrypted/`, or directly in ignored `work/source/decrypted/`. The most useful files are `cpk/Ange.cpk` and a decrypted executable if available; screenshots of menus and dialogue are also needed for width measurements. A readable CPK signature will allow archive inspection and script extraction. A decrypted copy of the 24 manual pages would allow visual UI and terminology checks.

VitaShell can expose files through a mounted PFS filesystem, as described by the [psvpfstools author](https://github.com/motoharu-gosuto/psvpfstools#introduction). A copied install folder may still retain encryption; check signatures before accepting it as decrypted. The same project documents a PC PFS decryptor requiring additional per-title license material and a F00D implementation/cache. No license/account material was obtained, requested, or sent to an external service during this inspection.

## Extractor provenance and reproduction

Source: [official pkg2zip repository](https://github.com/mmozeiko/pkg2zip), upstream commit `9222c4e00235dfe7914e9db0cc352da07e63d9f9`; sources were downloaded from its master branch and compiled with the available MinGW GCC. Upstream code is in `tools/pkg2zip/` as ignored local dependencies. pkg2zip is public-domain software. Its [README](https://github.com/mmozeiko/pkg2zip/blob/master/README.md#usage) explicitly supports unpacking without a zRIF argument and describes `-l` and `-x`.

- Input SHA-256: `962498429645BF92D0171280B075629FF6DC8100F365CE43805D2CD3E897EBCB`.
- Locally compiled extractor SHA-256: `A4A0E4E2F204B9F44E14C85332E9FA81402E2D72AB035538E0924572C764605F`.
- Compiler: MinGW GCC 12.2.0, x86_64-posix-seh-rev2.

```powershell
# Read-only metadata sample first.
$package = Get-ChildItem -LiteralPath . -Filter *.pkg -File | Select-Object -First 1
$env:PYTHONIOENCODING = 'utf-8'
python tools/pkg_probe.py $package.FullName

# Read-only extractor recognition, then inspect output before extraction.
& ./tools/pkg2zip/pkg2zip.exe -l $package.FullName

# Run in a new ignored source directory; upstream creates app/PCSG00597.
New-Item -ItemType Directory -Path work/source/pkg -Force | Out-Null
Push-Location -LiteralPath work/source/pkg
& ../../../tools/pkg2zip/pkg2zip.exe -x $package.FullName
Pop-Location
```

Build command, run inside `tools/pkg2zip` after obtaining upstream C/H sources:

```powershell
$sources = Get-ChildItem -LiteralPath . -Filter *.c -File | ForEach-Object Name
gcc -std=c99 -O2 -DNDEBUG -D_GNU_SOURCE -maes -mssse3 -mpclmul -msse4 -o pkg2zip.exe @sources
```
